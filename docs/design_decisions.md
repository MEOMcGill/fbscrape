# Key Design Decisions

Numbered decisions recorded as they were made. Cross-referenced from `CLAUDE.md`.

1. **Email OR Phone** — accounts identified by either, enforced by SQL CHECK constraint. `Account.identifier` returns email if present, else phone.
2. **GraphQL viewer detection over DOM** — login status checked by intercepting the first GraphQL response with non-null `data.viewer`. No DOM polling; no race against page render.
3. **Human-like typing** — login form keystrokes use normal-distribution delays (`mean=100ms, std=30ms`).
4. **Cookies saved before browser close** — context errors otherwise corrupt the save.
5. **`wait_until="domcontentloaded"`** — Facebook's load event never fires on infinite-scroll feeds.
6. **Lock for lazy init** — `asyncio.Lock` around `WorkerPool` lazy-init prevents `gather()`-induced double-init.
7. **5-minute rotation cooldown** — `lock_until` on rotation prevents immediately re-acquiring the same account.
8. **Stall watchdog on GraphQL silence (manual only)** — keyed off `last_response_time`. Fires whether FB silences the endpoint or returns empty bodies. Hybrid uses different stop conditions (`end_cursor` null, oldest post < `start_unix`, no-progress streak).
9. **Self-signed fbcdn URLs, short TTL** — media URLs carry an `oh=` HMAC signature and an `oe=` expiry (hex-encoded unix seconds); no cookies/auth needed to fetch them. Empirically the TTL is **~4-5 days from scrape time**, not 30 — verified across 12k URLs from a 2026-05 scrape batch (uniform 4d for ~91%, 5d for ~9%). Expired URLs return HTTP 403 with `Bad URL hash`. Practical consequences: (a) run `download-media` within ~3 days of the scrape or pipeline it into the same run, (b) raw post JSONs older than ~5 days are media-irrecoverable without re-scraping. Per-URL expiry: `int(url.split('oe=')[1].split('&')[0], 16)`.
10. **Endpoint × mode registry** — `Query.ENDPOINT_REGISTRY` is the single source of truth for endpoints, modes, and per-(endpoint, mode) param defaults. Per-mode methods on `BrowserSession` handle dispatch via `Worker.ENDPOINT_MODE_METHODS`.
11. **Query is constructed exactly once** — `FacebookScraper.user_timeline` builds the canonical Query, validates, fills defaults. `BrowserSession` returns a `ScrapeOutcome` (Query-agnostic); `Worker` attaches the original Query via `ScrapingResult.from_outcome`. No drift between caller-spec and recorded-spec.
12. **Hybrid: `cursor=null` + `beforeTime` always set** — empirically confirmed FB's UI uses `cursor=null` whenever a date filter is active. Replays mirror that: every replay carries a non-null `beforeTime` (= `min(end_of_day(end_date), now_utc)`) so FB honors `cursor=null` on the first replay. `afterTime` stays at the captured `null` (FB's UI never sets it). See [`docs/hybrid/overview.md`](hybrid/overview.md).
13. **Hybrid: post auto-extraction off** — `ResponseInterceptor.extract_posts = False` for the duration of a hybrid scrape. Prevents the natural bootstrap PCTFRQ (no date filter) from leaking off-range posts into the result. All posts come from replays with explicit filters.
14. **`__csr` / `__dyn` are HasteBitMap telemetry, not auth** — from FB's bundled JS, both are bitmaps of bootloaded resources / dynamic JS modules. FB's own request builder will conditionally `delete v.__csr`. We currently live-splice the freshest values from natural GraphQL POSTs; the `freeze_tokens` experiment in the roadmap validates whether splicing matters.
15. **Per-call timeouts wrap renderer-prone awaits** — every `scroll()`, `check_error_conditions()`, `page.request.post()`, etc. is wrapped in `asyncio.wait_for(operation_timeout_seconds)` so a wedged renderer can't hang a scrape forever. Per-call patch; the proper fix (external watchdog task) is in the roadmap.
16. **Hybrid: cursor-reset detection + multi-leg resume** — empirically, after a variable number of paginations (median ~33 across 21 dumped scrapes, range 2–214) FB silently returns a degraded response: `has_next_page: true` and a fresh `end_cursor`, but the response shape collapses and the oldest creation_time jumps newer with zero post overlap. Detector lives in `_hybrid_pagination_loop`: if the per-batch `detector_anchor` jumps newer by more than `HYBRID_CURSOR_RESET_JUMP_SECONDS` (= 7 days) vs. the previous iter, dump a 20-iter rolling window to `tmp/hybrid/cursor_reset/<handle>/<UTC_ts>/` and return `'cursor_reset'`. **Endpoint-aware anchor**: UserTimeline / Search use absolute `oldest_in_batch`; GroupTimeline uses `second_oldest_in_batch` (avoids false positives from the per-batch bootstrap-edge "highlight" outlier). `Worker.execute_task` recognizes the result string, locks the account 30 min, then `FacebookScraper.user_timeline` resumes with `end_date` advanced backward to the oldest collected post's day, capped at `MAX_CURSOR_RESET_RESUMES` (= 5). GroupTimeline does NOT multi-leg-resume. Terminal result strings: `'cursor_reset_max_retries'`, `'cursor_reset_no_progress'`, `'cursor_reset_no_posts'`.
17. **Post-id dedup at `ResponseInterceptor.add_posts`** — `add_posts` filters by `post_id` against `self.seen_post_ids` before appending. Without dedup, FB cursor-degraded responses would inflate `len(self.posts)` and let the no-progress backstop fail to fire. Posts without a `post_id` are appended as-is.
18. **Response-shape error is terminal, not retryable** — when the hybrid loop sees `posts_in_resp > 0` but `oldest_in_batch is None` (every post had an unrecognized timestamp metadata-strategy typename), the loop returns `'response_shape_error'`. Worker preserves partial data, does not rotate, does not mark inactive, does not burn a retry slot — the condition signals a structural bug (FB shape change), not an instance-specific failure.
19. **Pluggable stop-condition framework + sort-aware defaults** — `_hybrid_pagination_loop` walks an ordered list of `StopCondition` objects per iter (`fbscrape/stop_conditions.py`). Default sets are assembled per (endpoint, mode, sorting_setting) by `assemble_default_stop_conditions`. **Sort default flip for GroupTimeline**: `CHRONOLOGICAL` correlates with FB suspending accounts; `TOP_POSTS` (FB's UI default) is the lowest-fingerprint choice. Chronologically-ordered responses get `OldestInBatchBelowStartDate` + `CursorReset`; non-chronological sorts drop those and rely on `ConsecutiveOutOfRange(20)` instead.
20. **Optional dates per endpoint, FB-UI-fingerprint-aligned defaults.**
    - **UserTimeline** — `end_date` auto-fills to today UTC; `beforeTime` always injected (KDD 12). `start_date` stays None when omitted; date-bounded stops no-op via existing None guards.
    - **GroupTimeline** — both dates stay None when omitted (`default_end_to_today=False`); no `beforeTime`/`afterTime` wire variable exists for GCFRSPQ.
    - **Search** — still requires both dates until the no-date URL form is verified.
    - **Filename**: stems are `<handle>_<endpoint>_<mode>.jsonl.gz` (no date segment). `_build_stem()` and `_existing_output_for_stem()` in `cli.py` centralize matching so `--continue` / `--skip-existing` work across date-range changes.
    - **Cursor_reset multi-leg**: only engages when `end_date is not None`; otherwise cursor_reset is terminal.
21. **Hybrid: `end_cursor` extraction is chunk-path aware, not first-match** — FB's @stream/@defer JSONL responses contain multiple chunks each with a `path` field. The page-level pagination cursor lives in the shortest-path chunk (absent path → length 0). Reels-attachment deferred chunks at deeper paths (5+ elements) carry their own `end_cursor`s that arrive BEFORE the page-level chunk when a batch contains a Reel. A naive first-match extractor silently picks the wrong cursor → server-side `field_exception` on the next replay. Fix: `_hybrid_extract_end_cursor` returns the cursor from the shortest-path chunk; falsy cursor there is the legitimate end-of-feed signal.
22. **Resume reads are streamed, not loaded; post-scrape merge runs off the event loop.**
    - **Pre-scrape**: `scraper._stream_resume_state` uses ijson to walk only `last_cursor` + per-record `post_id`, avoiding materialization. Called via `asyncio.to_thread` so reads parallelize.
    - **Post-scrape**: `cli._finalize_continue_result` dispatched via `asyncio.to_thread` + `asyncio.create_task` per result; `await asyncio.gather(*finalize_tasks)` joins before scraper context exits. Prevents serialized post-processing when multiple targets complete concurrently.
    - *(Note: superseded for JSONL format by KDD 24 — `--continue` is now an append, so pre-scrape uses tail-read instead.)*
23. **Scroll-based rotation reads a per-session counter, not the DB.** `Worker.scroll_count` sums `BrowserSession.scrolls_recorded` (per-session integer, zeroed on rotation/init/close). DB columns (`scroll_count_per_endpoint_total`, `scroll_count_overall_24h`) are cumulative-lifetime and over-count across worker instances — their real consumer is `AccountsPool._order_by = "scroll_count_overall_24h ASC"` for account-selection prioritization.
24. **One-post-per-line JSONL is the on-disk format; `--continue` appends.** Scrape outputs are `<stem>.jsonl.gz` where each line is `{query, result, time_started, time_taken, last_cursor, data: <one Story>}`. Why: the prior monolithic envelope caused OOM on `--continue` (300–400 MB gzip → 8–15 GB of live Python objects; RSS hit 46 GiB, `CONSTRAINT_MEMCG`, 2026-06-03). JSONL makes `--continue` an O(new leg) append — prior file never loaded. Per-line semantics: `result`/`time_taken` are `null` mid-leg and stamped on the final line. **Resume** reads the JSONL tail (`read_resume_tail` — last ~150 lines → `last_cursor` + recent `post_id`s for dedup). **Dual-format everywhere**: `looks_like_jsonl` routes readers; `jsonl_store.load_scrape_file` handles both. **Auto-unstick** appends a status-only line (`data: null`) with a deeper cursor. **Migration**: legacy envelope converted to JSONL on first `--continue`; `fbscrape utils convert-to-jsonl` does the corpus up-front. `_json_default` handles `Decimal` (ijson yields it, `json.dumps` can't serialize it).
25. *(superseded by KDD 24)* — the disk-to-disk streaming merge is gone; `--continue` is a plain append.
